# Crush Lab

좋아하는 마음이 어떻게 움직이는지 알아보는 검사.

**<https://crush-lab.kangchiteacher123.workers.dev>**

`main` 에 머지되면 Cloudflare가 자동으로 빌드·배포한다. 직접 올릴 일은 없다.

---

## ⚠️ 지금은 빈 도화지다

**검사 내용이 전부 비어 있다.** 화면·채점·배포는 다 돌아가지만 들어갈 내용이 없다.

그 전까지 들어 있던 문항·서사·유형·캐릭터는 **기계가 도는지 확인하려고 급조한
테스트 데이터**였고, 2026-08-14에 전부 지웠다. 설계된 것이 아니므로
**참고하거나 되살릴 이유가 없다.**

문항을 설계하려면 → **[인수인계 문서](docs/HANDOFF.md)** 부터 읽을 것.

채워야 할 파일 다섯 개:

```
src/data/axes.ts       무엇을 잴 것인가
src/data/intro.ts      시작 질문 (아바타 재료를 모으는 곳)
src/data/questions.ts  본 문항
src/data/scenes.ts     서사 (비워도 검사는 돌아간다)
src/data/avatar.ts     아바타 조각
```

---

## 시작하기

```bash
npm install
npm run dev      # http://localhost:4321
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` | `dist/` 에 정적 HTML을 뽑는다 |
| `npm run preview` | 빌드 결과 확인 |
| `npm run check:questions` | **문항 손봤으면 반드시** — 안 나가는 문항, 출제량 편차 등을 잡는다 |

## 어디를 고치면 되나

| 하고 싶은 것 | 고칠 파일 |
| --- | --- |
| 무엇을 잴지 정하기 | `src/data/axes.ts` |
| 문항 쓰기 | `src/data/questions.ts` |
| 시작 질문 쓰기 | `src/data/intro.ts` |
| 서사 쓰기 | `src/data/scenes.ts` |
| 아바타 조각 붙이기 | `src/data/avatar.ts` |
| 문항 뽑는 규칙 | `src/engine/select.ts` |
| 데이터 모양 자체 | `src/engine/types.ts` — 안 맞으면 고쳐도 된다 |
| 색·글꼴 | `src/styles/app.css` 맨 위 토큰 |
| 배포 주소 | `astro.config.mjs` 의 `site` |
| 채점 방식 | `src/engine/score.ts` — **권하지 않는다** ([이유](docs/HANDOFF.md)) |

## 1. 검사 설계 ← 지금 여기

- [ ] **무엇을 잴 것인가** — 축 정의. 이게 정해져야 문항을 쓸 수 있다
- [ ] **결과를 어떤 모양으로 낼 것인가** — 유형? 점수? 서술형? (축 개수가 여기서 역산된다)
- [ ] 시작 질문 목록 — 아바타 재료 + 분기 조건
- [ ] 시작 질문 순서 = 아바타가 그려지는 순서
- [ ] 본 문항 — 축마다 최소 6~8개
- [ ] 한 사람당 출제 문항 수 결정
- [ ] 선택지형 / 슬라이더형 비율
- [ ] 선택지 개수 통일 (들쭉날쭉하면 화면 높이가 매번 바뀐다)
- [ ] 선택지 길이 상한
- [ ] 조건부 문항 설계 (`show`)
- [ ] 문항 태그 체계 (`tags` — 장면 배치·주제 분류)
- [ ] 성별 중립 표현 점검 — 동성을 좋아하는 이용자도 쓸 수 있게
- [ ] 좋아하는 상대의 성별·특징 분기 설계
