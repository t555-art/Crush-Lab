# 구조 설명

## 세 층으로 나눠져 있다

이게 이 저장소의 핵심이다.

```
데이터   src/data/     무엇을 물어보는가        ← 자주 바뀐다
규칙     src/engine/   누구에게 무엇을 내는가    ← 가끔 바뀐다
채점     score.ts      어떻게 점수를 매기는가    ← 안 바뀐다
```

**서로 모른다.** 문항을 통째로 갈아엎어도 규칙과 채점은 그대로 돌고,
뽑는 규칙을 바꿔도 문항과 채점은 그대로다.

이렇게 나눈 이유는 콘텐츠를 쓰는 사람과 코드를 만지는 사람이 다르기 때문이다.
문항을 고치려고 코드를 읽어야 하면 협업이 안 된다.

## 폴더

```
src/
  data/                채울 것들. 지금 전부 비어 있다
    axes.ts            축 정의
    intro.ts           시작 질문 (아바타 재료)
    questions.ts       본 문항
    scenes.ts          서사 (선택)
    avatar.ts          아바타 조각
  engine/
    types.ts           데이터 계약 — 안 맞으면 고쳐도 된다
    select.ts          문항 고르는 규칙
    score.ts           채점
  scripts/player.ts    화면 진행
  layouts/Base.astro   공통 head · OG 태그
  pages/               랜딩 · 검사 · 404
  styles/app.css       스타일 전부
public/art/            그림
tools/                 검사 도구
```

## 서사와 문항이 분리돼 있다

`scenes.ts` 는 **이야기만** 갖는다. 어떤 문항이 나올지는 조건으로만 적는다.

```ts
{ kind: 'question', pick: { tags: 'classroom' } }
```

`select.ts` 가 실행 시점에 실제 문항을 채운다. 그래서:

- 문항을 바꿔도 → 이야기는 그대로
- 이야기를 바꿔도 → 채점은 그대로
- 뽑는 규칙을 바꿔도 → 위 둘 다 그대로

**장면이 하나도 없으면 문항만 순서대로 나간다.** 서사 없이도 검사는 돌아간다.

## 특성(traits)이 세 곳을 잇는다

선택지가 붙이는 꼬리표 하나가 세 가지를 동시에 움직인다.

```ts
{ text: '여자', traits: { gender: 'f' } }
```

1. **아바타** — `avatar.ts` 의 조각 중 `when: { gender: 'f' }` 인 것이 켜진다
2. **그림 분기** — 장면 그림의 `variants` 가 조건에 맞는 것으로 바뀐다
3. **출제 조건** — `show: { gender: 'f' }` 인 문항이 나갈 수 있게 된다

하나의 개념으로 세 가지를 처리하므로, 새 분기를 넣을 때 특성 하나만 추가하면 된다.

## 채점은 왜 그렇게 생겼나

`score.ts` 의 정규화는 **바꾸지 않는 게 좋다.**

점수를 그냥 더하면 "그 사람에게 어떤 문항이 뽑혔는지"가 결과에 섞여 들어간다.
조건부 출제 때문에 사람마다 문항이 달라지는 구조에서는 치명적이다.
'직진' 쪽 점수를 주는 문항이 우연히 많이 뽑힌 사람은 실제 성향과 무관하게
직진으로 판정된다.

그래서 이렇게 한다.

1. 그 세트를 **무작위로 찍었을 때의 기댓값**을 구한다 → 이게 판정선
2. 실제 점수가 거기서 얼마나 벗어났는지 본다
3. 그 방향으로 갈 수 있었던 **최대 이탈폭**으로 나눈다

세트가 어느 쪽으로 치우쳐 있든 판정선이 자동으로 가운데 온다.
축이 몇 개든, 문항이 선택지형이든 슬라이더형이든 그대로 돈다.

## 문항을 손봤으면 반드시

```bash
npm run check:questions
```

눈으로는 못 잡는 것들을 잡는다.

- id 중복, 없는 축을 가리키는 오타
- 어떤 축도 재지 않는 문항
- **아무에게도 안 나가는 문항** — `show` 조건이 실제 특성 조합과 안 맞는 경우
- **사람마다 출제량 차이** — 어떤 사람은 10문항, 어떤 사람은 40문항
- 축별 문항 수 불균형
- 무작위 응답으로 채점까지 돌려서 터지는지

## 데이터를 TS로 둔 이유

JSON이 아니라 TypeScript 파일이다.

- 오타·형식 오류가 **빌드에서 잡힌다.** JSON이면 실행해봐야 안다
- 파일 안에 **설명을 주석으로 남길 수 있다.** 채우는 사람이 예시를 보고 시작할 수 있다

문항이 많아지면 `questions.ts` 를 폴더로 쪼개고 한곳에서 합쳐 내보내면 된다.

## 알고 있는 한계

- **공유 썸네일이 SVG다.** 카카오톡·페이스북은 SVG를 못 읽는다. 공개 전에 PNG로 바꿔야 한다
- **결과 화면이 임시다.** 축 게이지만 나온다
- **문항이 전부 번들에 실린다.** 지금은 0개라 문제없지만, 수백 개가 되면 분할이 필요하다
