# 인수인계 — 문항·스토리·미술을 맡은 쪽에게

이 저장소에서 **검사 내용을 설계**하는 사람(과 그쪽 Claude)을 위한 문서다.

---

## 역할 분담

| | 담당 |
| --- | --- |
| **내용** — 문항, 스토리, 대사, 결과 텍스트 | **친구 쪽** |
| **미술** — 캐릭터 부품, 배경, 스타일 | **친구 쪽** |
| **기능** — 엔진, 화면, 연출, 출제 알고리즘, 배포 | **코드 쪽** |

위는 **주 담당**이지 담장이 아니다.
**상대 영역을 건드려도 된다.** 문항 쓰는 쪽이 화면을 고쳐도 되고,
코드 쪽이 문구를 다듬어도 된다. 하고 싶으면 하면 된다.

**딱 하나만 지키면 된다 — 무엇을 했는지 [`PROGRESS.md`](PROGRESS.md) 에 남길 것.**

그것만 있으면 서로 겹쳐서 같은 걸 두 번 만드는 일도,
상대가 고친 걸 모르고 되돌리는 일도 안 생긴다.
길게 쓸 필요 없다. 파일 이름과 한 줄이면 충분하다.

---

## 먼저: 여기 있던 것들은 전부 임시였다

⚠️ **아주 중요하다. 이걸 모르면 엉뚱한 걸 물려받는다.**

이 저장소에 있던 검사 내용은 **기계가 돌아가는지 확인하려고 급조한 테스트 데이터**였다.
설계된 것도, 검증된 것도 아니고, **지켜야 할 이유가 하나도 없다.**

| 임시였던 것 | 왜 그랬나 |
| --- | --- |
| 문항 35개 | "축 4개니까 축당 8개쯤" 이라고 대충 잡은 숫자 |
| 장면 7개 | 하루를 7토막 낸 것뿐 |
| 07:10 · 07:50 … 시각 | 그럴듯해 보이라고 적음 |
| 하루 서사(기상→등교→…→밤) | 뼈대 시연용으로 지어낸 것 |
| 축 4개 (속도·표현·무대·투자) | 옛 HTML 버전에서 가져온 것 |
| 크리스탈 16유형, 요정 캐릭터 | 옛 버전 것. **안 쓴다** |
| 문항 364개 | 옛 버전 것. **안 쓴다** |

**전부 삭제했다.** 참고하지 말고, 되살리지 말고, 영향받지 마라.
지금은 기계만 남은 **빈 도화지**다.

## 만들려는 것

사람이 정한 구상이다. 기능은 전부 구현해뒀다.

### 1. 시작 질문 — 답할수록 내 아바타가 그려진다

성별·나이·학교 등을 물어본다. **답할 때마다 화면의 아바타에 부품이 하나씩 붙는다.**
머리가 붙고, 체형이 정해지고, 얼굴이 생긴다.

그다음 **직접 다듬는 화면**이 나온다. 자동으로 정해진 것 중 마음에 안 드는 것만 바꾼다.

### 2. 스토리 일러스트에 내 아바타가 그대로 나온다

완성된 그림 한 장을 넣는 게 아니다.
**머리·체형·얼굴 같은 부품 자리를 만들어두고 거기에 그 사람 것이 들어간다.**
좋아하는 상대 캐릭터도 같은 방식으로, 응답에 따라 다르게 조립된다.

### 3. 터치하면 대사가 하나씩 쌓이고, 그 뒤에 질문이 뜬다

화면을 누를 때마다 지문·대사가 **누적**된다 (지워지고 바뀌는 게 아니라).
앞의 말은 흐려지고 최근 것이 또렷하다.
대사가 다 나온 뒤에야 **질문창이 그 위로 은은하게 떠오른다.**

### 4. 폰 세로 화면 전용

터치로만 진행한다.

### 5. 문항 분량

| | |
| --- | --- |
| 전체 설문 | **120문항 이내** |
| 스토리 구간 | **약 100문항** |
| 실제 만들 문항 | **그보다 훨씬 많이** ← 아래 참고 |

100문항을 매번 **랜덤이지만 시간대에 맞게** 뽑으려면 후보가 훨씬 많아야 한다.
스토리로 지루하지 않게 만드는 게 목표다.

### 6. 불가능한 상황은 안 나온다

남고 다니는 사람에게 "복도에서 좋아하는 애를 마주쳤다"는 나올 수 없다.
경우의 수마다 대응이 되어 있어야 한다.

### 7. 항목별로 고르게 물어본다

자신감만 20문항 묻고 적극성은 2문항이면 결과가 반쪽이다.
**역할별 최소치를 채운 뒤** 나머지를 무작위로 뽑는다.

### 8. 결과

자기 유형이 나오고, 항목별 점수와 그 밖의 정보가 붙는다.
유형을 캐릭터로 낼지 다른 방식으로 낼지는 **아직 안 정했다.**

## 데이터 계약

`src/engine/types.ts` 에 전부 있다. **제안이지 확정이 아니다.**
안 맞으면 코드 쪽에 요청해서 고치면 된다.

### 축

```ts
{ id:'confidence', name:'자신감', posLabel:'당당', negLabel:'조심' }
```

개수 자유. 축이 늘면 축당 문항이 더 필요해진다.

### 특성 (traits) — 이게 전부를 잇는다

선택지가 붙이는 꼬리표 하나가 **네 곳을 동시에** 움직인다.

```ts
{ text:'여자', traits:{ gender:'f' } }
```

1. **내 아바타** 부품 선택
2. **상대 캐릭터** 부품 선택 — `crush.` 를 앞에 붙인다: `{ 'crush.gender':'m' }`
3. **문항 필터** — `show:{ gender:'f' }`
4. **장면 필터** — `when:{ school:'!boys' }`

값 앞의 `!` 는 부정이다. `'!boys'` = 남고가 아닐 때.

### 선택지형 문항

```ts
{
  id:'q-001', kind:'choice',
  text:'쉬는 시간 10분.\n걔가 혼자 앉아 있다.',
  aspect:'initiative',           // 무엇을 보는 문항인가 (균등 출제에 쓰임)
  slots:['classroom'],           // 어느 시간대·장면에 어울리는가
  show:{ school:'!boys' },       // 이 사람에게 낼 수 있는가
  options:[
    { text:'가서 말 건다', score:{ initiative:3 } },
    { text:'그냥 본다',   score:{ initiative:-2 } },
  ],
}
```

### 슬라이더형 문항

```ts
{
  id:'q-002', kind:'scale',
  text:'읽씹당하면 하루 종일 신경 쓰여',
  aspect:'confidence', slots:['night'],
  minLabel:'전혀', maxLabel:'완전',
  steps:5,
  weight:{ confidence:-3 },
}
```

응답 위치를 -1~+1로 환산해 `weight` 를 곱한다.
`steps` 홀수 → 가운데(중립)가 생기고 그게 기본값이다.
안 움직이고 넘기면 0점이 된다.

### 장면

```ts
{
  id:'classroom', title:'교실', label:'아침 · 교실',
  slot:'classroom',                    // 이 장면의 시간대
  when:{ school:'!boys' },             // 남고면 이 장면 자체가 없다
  background:{ src:'...', alt:'...' },
  cast:[                               // 이 장면에 서 있는 인물
    { who:'self',  x:30, y:88, scale:0.9 },
    { who:'crush', x:70, y:88, scale:0.9, flip:true },
  ],
  beats:[
    { kind:'narration', text:'교실에 들어선다.' },
    { kind:'line', speaker:'친구', text:'야 저기 봐.' },
    { kind:'question', pick:{ slot:'classroom' } },   // 조건에 맞는 문항 하나
    { kind:'question', id:'q-001' },                  // 특정 문항 고정
  ],
}
```

`x`/`y` 는 화면 비율(%), `y` 는 발이 닿는 위치다.

### 캐릭터 부품

```ts
{ id:'hair-long', slot:'hair', z:3, src:'/art/parts/hair-long.webp',
  label:'긴 머리', when:{ hair:'long' } },
{ id:'body-mid',  slot:'body', z:0, src:'/art/parts/body-mid.webp',
  label:'보통' },                     // 조건 없음 = 그 슬롯의 기본값
```

- 슬롯 하나당 부품 하나가 선택되어 `z` 순서로 겹쳐진다
- `for:'self'` / `for:'crush'` 로 나눌 수 있다. 안 적으면 둘 다
- `label` 은 직접 고르는 화면에 뜬다
- **모든 부품이 같은 캔버스 크기·같은 기준점**으로 그려져야 안 어긋난다

## 친구 쪽에서 만들어야 할 것

### 1. 축

무엇을 잴 것인가. **이게 정해져야 문항을 쓸 수 있다.**

### 2. 시작 질문

- 아바타 재료(`traits`)와 분기 조건을 여기서 모은다
- **순서를 아바타가 눈에 띄게 변하는 순으로.** 첫 질문에 답했는데 그림이 그대로면
  "답할수록 그려진다"는 느낌이 첫 질문부터 죽는다. 큰 것(체형·머리)부터가 낫다
- 좋아하는 상대에 대한 질문도 여기서 (`crush.` 특성)

### 3. 문항 — 여기가 제일 큰 일이다

**100문항을 뽑으려면 후보가 훨씬 많아야 한다.** 얼마나 더 필요한지는 이렇게 정해진다.

- 조건(`show`)이 붙은 문항은 일부 사람에게만 나간다 →
  **조건마다 대체 문항이 있어야** 그 사람도 100문항을 채운다
- 시간대(`slots`)별로 나뉜다 → 장면 수만큼 나눠 담아야 한다
- 역할(`aspect`)별 최소치를 채워야 한다

거칠게 잡으면 **300~400문항**은 있어야 100문항을 매번 다르게, 조건에 맞게 낼 수 있다.

문항마다 반드시 붙일 것:

| 항목 | 왜 |
| --- | --- |
| `aspect` | 이게 없으면 항목별 균등 출제가 안 된다 |
| `slots` | 이게 없으면 아침 장면에서 밤 이야기가 나온다 |
| `show` | 이게 없으면 남고생에게 복도 문항이 나간다 |

### 4. 장면과 대사

- 무엇을 따라갈지 (하루? 학기?)
- 장면마다 지문·대사, 인물 배치
- **불가능한 조합의 장면에는 `when` 을 걸 것.** 그리고 그 경우를 위한
  **대체 장면**도 필요하다 — 안 그러면 그 사람만 문항 수가 적어진다

### 5. 캐릭터 부품 (미술)

⚠️ **그리기 전에 [`ART-SPEC.md`](ART-SPEC.md) 를 먼저 읽을 것.**
규격이 어긋난 채로 50장을 뽑으면 전부 다시 그려야 한다.

- 캔버스 1024×1536, 배경 투명, 기준선 고정
- 정렬 가이드(`public/art/_guide.svg`)를 ChatGPT에 첨부해서 생성
- 3장쯤 뽑았을 때 `npm run check:art` 와 `/art` 화면으로 확인하고 넘어갈 것

조합으로 만들면 장수가 확 준다 — 머리 4 × 체형 3 × 얼굴 4 = 48가지가 그림 11장이면 된다.

### 6. 결과 내용

유형을 어떤 모양으로 낼지, 본문을 어떻게 쓸지.

### `npm run check:questions` 가 잡아주는 것

문항이 수백 개가 되고 조건이 얽히면 **눈으로는 절대 못 잡는다.**

- id 중복, 없는 축을 가리키는 오타
- 어떤 축도 재지 않는 문항
- 축·역할별 문항 수 부족 (6개 미만이면 경고)
- **아무에게도 안 나가는 문항** — `show` 조건이 실제 특성 조합과 안 맞는 경우
- **사람마다 출제량 차이** — 남고생만 문항이 적은 상황을 여기서 잡는다
- 중복 출제
- 무작위 응답으로 채점까지 돌려서 터지는지

## 채점만은 그대로 두기를 권한다

`src/engine/score.ts` 의 정규화다.

점수를 그냥 더하면 **"그 사람에게 어떤 문항이 뽑혔는지"가 결과에 섞여 들어간다.**
조건부 출제 때문에 사람마다 문항이 달라지는 구조에서는 치명적이다.
'적극' 쪽 점수를 주는 문항이 우연히 많이 뽑힌 사람은 실제 성향과 무관하게
적극적으로 판정된다.

그래서 무작위 응답의 기댓값을 판정선으로 삼고, 거기서 벗어난 정도를
그 방향의 최대 이탈폭으로 나눈다. 세트가 어느 쪽으로 치우쳐 있든
판정선이 자동으로 가운데 온다.

## 오늘 정하면 좋은 순서

1. **무엇을 잴 것인가** (축)
2. **결과를 어떤 모양으로 낼 것인가** (축 개수가 여기서 역산된다)
3. **시작 질문** — 아바타 재료 + 분기 조건
4. **장면 목록** — 시간대 태그(`slots`)의 이름이 여기서 정해진다
5. **문항** — 위 셋이 정해져야 `aspect`·`slots`·`show` 를 붙일 수 있다

## 참고: 지난번에 걸렸던 것들

- **선택지 개수가 들쭉날쭉하면** 화면 높이가 매번 바뀌어 눈이 피로하다
- **선택지가 길면** 두 줄로 넘어가 화면 아래가 넘친다. 상한을 정해두면 좋다
- **문항이 장면 맥락과 안 맞으면** 몰입이 깨진다. `slots` 로 묶어두면 걸러진다
- **밝은 일러스트 위 흰 글씨**는 안 읽힌다. 질문창이 자기 바닥을 깔도록 처리해뒀지만,
  그림이 들어오면 다시 확인이 필요하다
