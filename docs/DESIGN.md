담당은 내용 쪽이다. 기능 쪽 계약은 [`HANDOFF.md`](HANDOFF.md), 요청은 [`PROGRESS.md`](PROGRESS.md).

## 1. 무엇을 재는가 — 축 4개

| id | 이름 | + | − | 무엇을 보는가 |
| --- | --- | --- | --- | --- |
| `anxiety` | 신호 민감도 | 예민 | 태연 | 상대 반응 하나에 얼마나 흔들리는가 |
| `avoid` | 거리 조절 | 방어 | 개방 | 가까워지는 것 자체가 편한가 부담스러운가 |
| `move` | 행동 | 직진 | 관망 | 먼저 움직이는가 기다리는가 |
| `tempo` | 속도 | 금사빠 | 늦사빠 | 확신까지 걸리는 시간 |

### 왜 이 넷인가

`anxiety` 와 `avoid` 는 **애착 이론(ECR-R)** 에서 그대로 가져왔다.
성인용 척도지만 청소년판이 별도로 검증돼 있고(12~17세 805명 표본에서 2요인 구조 확인),
두 차원이 **서로 독립**이라는 게 문서화돼 있다. 이게 결정적이다 —
축끼리 상관이 높으면 16유형 중 몇 개는 사실상 아무도 안 나온다.

`move` 와 `tempo` 는 척도에서 온 게 아니라 **장면 안에서 행동으로 갈리는 축**이다.
스토리로 굴러가는 검사라서, 화면에서 눈에 보이는 선택으로 나뉘는 축이 최소 둘은 필요하다.

### 축으로 안 만든 것들

| | 왜 뺐나 | 어디로 갔나 |
| --- | --- | --- |
| 거절민감성 (Downey) | `anxiety` 와 상관이 너무 높다. 둘 다 축이면 유형 공간이 접힌다 | 결과지 하위 지표 (`tags`) |
| 사랑유형 6종 (Lee/LAS) | 확인적 요인분석에서 6요인 구조가 안 맞는 것으로 보고됨 | 결과지 하위 지표 |
| 자존감·인기 | 연애 성향이 아니라 그 배경 | 결과지 보조 서술 |

하위 지표는 축이 아니라 **선택지의 `tags`** 로 집계해서 결과 문장을 고르는 데 쓴다.
유형 판정에는 영향을 주지 않는다.

### ★ 제일 자주 틀리는 지점 — `avoid` 와 `move` 는 다르다

```
avoid = 가까워지는 것 자체가 불편한가   (의존 · 속마음 · 거리)
move  = 먼저 움직이는가                (말 걸기 · 약속 · 고백)
```

두 축이 헷갈리면 유형이 엉킨다. 구분이 되는 예를 보면 명확하다.

| 사람 | avoid | move |
| --- | --- | --- |
| 가볍게 훅 들어갔다가 깊어지면 빠지는 | 높음 | 높음 |
| 3년째 혼자 좋아하는 | 낮음 | 낮음 |
| 다 퍼주는데 고백은 못 하는 | 낮음 | 낮음 |
| 들이대지만 진심은 안 꺼내는 | 높음 | 높음 |

**한 문항이 두 축을 동시에 재면 안 된다.** 문항마다 `aspect` 를 하나만 적는다.

## 2. 서사 — 생활 상황을 따라간다

등교 전 → 학교(교실·급식실·복도) → 하교 후 → 밤 → 주말/학원 → 데이트

### 왜 이 순서인가 — 그냥 하루 순서가 아니다

끌림이 실제로 만들어지는 기제가 셋으로 정리돼 있는데, 그게 장소 순서와 그대로 겹친다.

| 기제 | 내용 | 어느 장면 |
| --- | --- | --- |
| **근접·반복노출** | 가까이 있고 자주 보는 것만으로 호감이 생긴다 | 교실 · 급식실 · 복도 |
| **상호성** | 상대가 나에게 관심 있다는 신호 **하나**면 끌림이 켜진다. 눈길·질문·칭찬 한 번으로 충분하다고 보고됨 | 하교 후 |
| **자기개방** | 속마음을 **서로** 주고받아야 친밀해진다. 일방적이면 효과 없음 | 밤 · 폰 |

그다음이 의도적 만남(주말·학원)과 관계 성립(데이트)이다.

즉 **장소가 사적인 정도 = 관계의 진행도**다.
교실(공개, 또래가 봄) → 하굣길(둘만, 우연) → 폰(사적, 밤) → 주말(의도적 약속) → 데이트(확정).
날짜를 세지 않아도 진행이 된다. 이전 설계가 '하루' 로 실패한 이유가 여기서 풀린다 —
하루는 시간대와 관계 단계를 강제로 묶어서, 17:40 하굣길에서
"사귄 지 한 달째 연락 빈도" 를 묻는 일이 생겼다.

### 장면 15개 · slot 9개

| slot | 걔가 학교에 있을 때 | 학교 밖에 있을 때 | 기제 |
| --- | --- | --- | --- |
| `morning` | 아직 아무도 안 만났다 | (같음) | 기저선 |
| `commute` | 저 앞에 보인다 | **오늘은 못 본다** | 근접 |
| `class` | 같은 공간, 다른 온도 | **이 교실엔 걔가 없다** | 반복노출 |
| `lunch` | 자리가 하나 비어 있다 | **얘기로만 아는 사람** | 또래집단 |
| `hall` | 스쳐 지나가는 3초 | **복도에선 아무 일도 없다** | 상호성 신호 |
| `afterschool` | 같이 걸을 기회 | **만나려면 정해야 한다** | 상호성 |
| `night` | 읽음 표시는 떴는데 | (같음) | 자기개방 |
| `weekend` | 교복이 아닌 걸 처음 봤다 | **학원 가는 길** (학원인 경우) | 의도적 만남 |
| `date` | 둘이서만 | (같음) | 관계 성립 |

`class` 만 기준이 다르다 — **같은 반**이어야 교실에 걔가 있다(`meet: 'class'`).
나머지 학교 장면은 같은 학교면 된다(`meet: ['class','school']`).

## 2-1. 남고 · 여고를 어떻게 다루는가

### 문제

남고 다니는 사람이 여자를 좋아하면 교실·급식실·복도에 그 사람이 **있을 수가 없다.**
그런데 이건 `school` 만으로 판정이 안 된다 — **남고라도 상대가 남자면 학교에 있다.**
`(공학) OR (남고 AND 상대가 남자) OR (여고 AND 상대가 여자)` 인데
`Condition` 은 키를 AND 로만 묶어서 이런 OR 을 못 쓴다.

### 해법 — 두 키를 갈라 쓴다

유도하지 않고 **직접 물어본 답을 기준으로 삼는다.**

| 키 | 무엇을 정하는가 | 어디에 쓰나 |
| --- | --- | --- |
| `meet` | 걔를 **어디서 보는가** | **장면**이 갈린다 (`scenes.ts` 의 `when`) |
| `school` | 우리 학교가 **어떤 곳인가** | **문항 표현**이 갈린다 (문항의 `show`) |

둘을 분리하면 모순이 안 생긴다. 남고생이 `meet: 'academy'` 를 고르면
학교 장면에 걔가 안 나오고, 그건 `school` 값과 무관하게 항상 일관된다.

### 빼는 게 아니라 다른 이야기를 깐다

매일 못 보는 사람은 **연애의 모양 자체가 다르다.** 문항을 빼면 결과만 빈약해진다.

| | 같은 학교 | 학교 밖 (남고·여고 + 이성) |
| --- | --- | --- |
| 근접·반복노출 | 매일 봄. 가만있어도 호감이 쌓임 | **거의 없음** |
| 우연 | 복도·급식실에서 계속 생김 | **없음. 약속해야만 봄** |
| 결정적인 축 | 관망해도 관계가 굴러감 | **`move`(행동)** — 안 움직이면 아무 일도 안 일어남 |
| 폰 | 보조 수단 | **주무대** |
| 소문 | 학교에 금방 남 | 안 남. 편하지만 허전함 |

`meet` 별로 검증했다. 네 값 전부 **slot 9개 · 문항 자리 63개로 동일**하다.

```
meet=class     morning → commute-near → class-same  → lunch-near → hall-near → afterschool-near → night → weekend-out     → date
meet=school    morning → commute-near → class-alone → lunch-near → hall-near → afterschool-near → night → weekend-out     → date
meet=academy   morning → commute-far  → class-alone → lunch-far  → hall-far  → afterschool-far  → night → weekend-academy → date
meet=outside   morning → commute-far  → class-alone → lunch-far  → hall-far  → afterschool-far  → night → weekend-out     → date
```

조건부 장면은 항상 이렇게 짝을 맞춘다 — 안 그러면 그 사람만 검사가 짧아지고 채점이 흔들린다.
`when` 조건은 **서로 배타적이고 빠짐없이** 덮어야 한다.

### `school` 로 갈리는 문항 (아직 안 씀 — 1단계에서)

`school` 은 장면이 아니라 **문항 표현**에서 쓴다. 남고·여고 특유의 결이 있다.

- `school: 'boys'` / `'girls'` — 학교에 이성이 아예 없는 환경에서 생기는 것들.
  연애 얘기가 도는 방식, 소문의 구조, 이성을 대하는 감각이 무뎌지는 문제
- `school: 'co'` — 매일 같은 공간에 있어서 생기는 것들. 오해받기 쉬움, 티가 남

**반드시 짝으로 쓴다.** `show: { school: 'boys' }` 를 쓰면 같은 slot·같은 axis 로
`girls` 와 `co` 몫도 만든다.

### 조사한 것 — 단성학교 이용자를 위한 재료

**학술 쪽 (일관되게 재현됨)**

- 단성학교 졸업생은 이성 친구가 적고, **첫 데이트 연령이 늦고**, 사귄 사람 수가 적다.
  단성 교육이 이성과의 연애를 **지연·감소**시킨다
- **이성 앞 불안(mixed-gender anxiety)** 은 측정 도구가 있는 구성개념이다.
  **DAS-A**(Dating Anxiety Scale for Adolescents) 21문항을 11문항으로 줄여 쓴다.
  하위척도는 *부정적 평가에 대한 두려움*(3문항) · *잠재적 연애 상황에서의 사회적 고통*(4문항)
- 단성학교 학생은 **고등학교·대학 표본 양쪽에서** 이 불안이 높고 이성 친구가 적다.
  '성별 현저성'(성별을 더 의식함)도 높다
- 반대편에 **이성 관계 효능감**이 있다. 높으면 이후 연애 관여가 늘고,
  이성 앞 불안·사회불안과는 부적 상관

**한국의 실제 경로 (커뮤니티 후기)**

| 경로 | 내용 |
| --- | --- |
| 친구 소개 · 친구의 친구 | 같이 놀다가 생기는 인연. 가장 흔하다 |
| 연합 동아리 | 여고 동아리가 타 학교와 연합 활동 |
| 학교 축제 | 공연하면 번호를 물어보는 사람이 생긴다. 부스 블라인드 소개팅도 있다 |
| 학원 · 과외 | 근처에 이성 학교가 없으면 사실상 여기 의존 |
| 알바 | 편의점·카페·음식점. 알바생끼리 |

> ⚠️ **"미팅"·"과팅" 은 쓰지 말 것.** 주로 대학생 문화라 고등학생 문항에 넣으면 겉돈다.
> 같은 뜻이라도 **"친구가 소개해준다"** 로 쓴다.

**반영 방법**

1. **이성 앞 불안은 축이 아니라 하위 지표로.** `anxiety`·`avoid` 와 상관이 있어서
   축으로 만들면 유형 공간이 접힌다. 선택지에 `tags: ['mga']` 를 달아 집계하고
   결과지 서술에만 쓴다 — *"이성 앞에서 말이 안 나오는 건 성격이라기보다
   마주칠 일이 없어서 연습량이 부족한 쪽에 가깝다"* 같은 문장이 근거를 갖고 나간다.
   단성학교 이용자와 공학 이용자의 결과가 실제로 갈리는 지점이다
2. **소개·축제·알바는 문항 소재로** 먼저 쓴다 (`show: { school: ['boys','girls'] }`)
3. `meet` 선택지에 소개·축제·알바를 **값으로** 추가하는 건 보류.
   4개 → 7개로 늘리면 조합이 19,440 → 34,020 이 되어 검사 상한을 넘는다.
   코드 쪽에 요청한 "아바타 전용 특성 제외" 가 먼저다 (그러면 720조합이 된다)

### 분량

```
9 slot × 7문항 = 63문항   ← 한 명이 답하는 양
문항 풀 300~400개         ← 그중 약 18%만 만난다
```

`SURVEY.maxPerScene` 이 8이라 장면당 8을 넘지 못한다. 지금은 7씩 두고 여유를 남겼다.

## 3. 변수 — 시작 질문 9개가 만드는 분기

엔진은 **검사 도중에 특성을 안 쌓는다.** `resolve()` 가 스토리 시작 전에 한 번만 돌고,
스토리 문항의 `traits` 는 반영되지 않는다. 그래서 **모든 분기가 시작 질문에서 결정된다.**

| id | 키 | 값 | 쓰임 |
| --- | --- | --- | --- |
| `i-gender` | `gender` | m / f | 아바타 · 문항 분기 |
| `i-build` | `build` | slim / mid / big | 아바타만 |
| `i-hair` | `hair` | short / mid / long | 아바타만 |
| `i-vibe` | `vibe` | bright / quiet / blank | 아바타(표정) |
| `i-school` | `school` | co / boys / girls | 장면·문항 분기 |
| `i-crush-gender` | `crush.gender` | m / f | 상대 캐릭터 · 문항 분기 |
| `i-meet` | `meet` | class / school / academy / outside | **장면 분기의 핵심** |
| `i-status` | `status` | crush / some / dating / broke / none | 문항 분기 |
| `i-exp` | `exp` | none / few / many | 문항 분기 |

### `meet` 을 따로 물어보는 이유

"우리 학교에 그 사람이 있는가" 는 `school` 과 `crush.gender` 를 조합해야 알 수 있는데,
`Condition` 은 키를 **AND 로만** 묶는다. `(공학) OR (남고 AND 상대가 남자)` 같은 조건을 못 쓴다.
그래서 유도하지 않고 직접 물어본다. 이쪽이 더 정확하기도 하다 —
공학이어도 학원에서 만난 사람일 수 있다.

### 조합 수 상한

`check:questions` 가 모든 선택지 조합을 전수로 돈다. 상한은 20,000.

```
2 × 3 × 3 × 3 × 3 × 2 × 4 × 5 × 3 = 19,440
```

**여유가 거의 없다.** 시작 질문을 늘리려면 코드 쪽 요청 두 가지 중 하나가 먼저다
([`PROGRESS.md`](PROGRESS.md) 참고). `show`/`when` 에 실제로 쓰이는 키만 곱하게 하면
720조합으로 떨어져서 분기를 마음껏 늘릴 수 있다.

## 4. 문항 집필 규약

### 형식

| | 규칙 | 왜 |
| --- | --- | --- |
| 선택지 개수 | **4개 고정** | 개수가 들쭉날쭉하면 화면 높이가 매번 바뀐다 |
| 선택지 길이 | **22자 이내** | 넘으면 두 줄로 접히고 화면 아래가 넘친다 |
| 질문 길이 | 2줄 이내 (`\n` 한 번) | |
| 슬라이더 비율 | 전체의 **20~25%** | 선택지만 계속 나오면 지친다. 리듬용 |
| `aspect` | **반드시 하나만** | 없으면 균등 출제가 안 되고, 둘이면 축이 엉킨다 |
| `slots` | **반드시 하나 이상** | 없으면 아침 장면에서 겨울 얘기가 나온다 |

### 점수

- 한 문항은 **한 축만** 잰다 (`aspect` 와 같은 축)
- 선택지 4개의 점수는 그 축에서 **서로 갈려야** 한다. 전부 같으면 안 재는 문항이다
- 점수 폭은 `-3 ~ +3`. 극단 선택지에만 ±3 을 준다
- 중립 선택지("잘 모르겠다")는 0점. 한 문항에 하나까지만

### ★ 조건부 문항은 반드시 짝으로 쓴다

`show` 를 붙이면 그 사람에게만 나간다. **짝이 없으면 반대편 사람은 그 자리가 빈다.**
남고생만 문항이 8개 적어지고, 채점이 흔들린다.

```
show: { school: 'boys' }   ← 이걸 쓰면
show: { school: '!boys' }  ← 이것도 같은 slot·같은 axis 로 반드시
```

`check:questions` 의 "사람마다 출제량 차이" 경고가 이걸 잡는다.

### 성별 표현

- **기본은 성별 중립.** 상대는 '걔', '그 사람' 으로 쓴다
- 동성을 좋아하는 이용자도 그대로 쓸 수 있어야 한다. `crush.gender` 는
  **상대 캐릭터 그림**과 꼭 필요한 소수 문항에만 쓴다
- `gender` 로 가르는 건 표현 방식이 실제로 갈릴 때만.
  연구상 여자 쪽이 무리를 만드는 접촉을 먼저 하고 남자 쪽이 약속을 먼저 잡는
  경향이 보고돼 있어서, `peer`·`confess` 장면에서 주로 갈린다
- 가를 때는 **반드시 양쪽 다** 쓴다 (위 짝 규칙)

### 일러스트가 붙는 문항

장면 배경은 전부 그려진다 (`background.prompt` 에 생성 지시문이 있다).
그와 별개로, **그 장면 안에서 그림이 따로 붙을 특별한 순간**은 문항에 표시한다.

```ts
tags: ['art']
```

우산을 같이 쓰는 순간, 급식실에서 눈이 마주치는 순간처럼 그림이 있으면
확 살아나는 문항들이다. 나중에 이 태그로 걸러서 **일러스트 발주 목록**을 뽑는다
(경로·프롬프트·문항 본문을 묶어서 정리). 남발하면 그림 장수가 감당이 안 되니
**slot 당 2개까지**.

### 배분 목표

| slot | 무조건 | 조건부 | 계 |
| --- | --- | --- | --- |
| `morning` | 24 | 12 | 36 |
| `commute` | 24 | 12 | 36 |
| `class` | 24 | 20 | 44 |
| `lunch` | 24 | 16 | 40 |
| `hall` | 24 | 16 | 40 |
| `afterschool` | 24 | 16 | 40 |
| `night` | 24 | 16 | 40 |
| `weekend` | 24 | 20 | 44 |
| `date` | 24 | 20 | 44 |
| **계** | **216** | **148** | **364** |

'무조건' 24개 = 축 4개 × 6개. 어떤 사람이 와도 slot 하나에서 축당 6개는 고를 수 있다.
`SURVEY.minPerAspect` 가 6이라 이 숫자를 맞춘 것이다.
