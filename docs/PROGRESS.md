# 진행 기록

양쪽에서 각자 작업하고 있어서, **무엇을 했고 무엇을 정했는지** 여기에 남긴다.
서로의 작업이 겹치거나 어긋나는 걸 막는 게 목적이다.

## 쓰는 법

작업을 마치면 맨 위에 항목을 하나 추가한다. 최신이 위로 오게.

```markdown
## YYYY-MM-DD · 누가

**한 것**
- 짧게. 파일 이름을 같이 적으면 좋다

**정한 것**
- 뒤집기 어려운 결정만. 이유를 한 줄 붙인다

**넘기는 것 / 물어볼 것**
- 상대 쪽이 알아야 하거나 결정해줘야 하는 것
```

세 칸 다 채울 필요는 없다. 없으면 지운다.

## 2026-08-14 · 코드 쪽

**한 것**
- 검사 내용을 전부 삭제하고 빈 상태로 되돌렸다.
  지운 것: 옛 문항 364개, 크리스탈 16유형, 축 4개, 하루 서사 7장면,
  요정 캐릭터, 관련 자리표시자 이미지, 옛 `index.html` 추출 도구
- 데이터 계약을 새로 짰다 (`src/engine/types.ts`)
  - 선택지형 + 슬라이더형 문항
  - 특성(traits) — 아바타·상대 묘사·출제 조건에 함께 쓰임
  - 아바타 레이어 (`src/data/avatar.ts`)
  - 그림 조건부 교체 (`ArtSlot.variants`)
- 채점을 축 개수와 무관하게 돌도록 고쳤다. 축은 `src/data/axes.ts` 에서 읽는다
- 슬라이더 UI와 아바타 누적 렌더링을 붙였다 (`src/scripts/player.ts`)
- `npm run check:questions` 를 새 스키마에 맞게 다시 만들었다.
  아무에게도 안 나가는 문항, 사람마다 출제량 차이까지 잡는다
- 인수인계 문서를 썼다 (`docs/HANDOFF.md`)

**정한 것**
- 데이터 파일을 JSON 대신 TS로 뒀다. 타입이 걸려서 오타·형식 오류가
  빌드에서 잡히고, 파일 안에 설명을 주석으로 남길 수 있다
- 채점 정규화(무작위 기댓값 대비)는 유지했다. 조건부 출제 구조에서는
  이게 없으면 "어떤 문항이 뽑혔는지"가 결과에 섞인다

**넘기는 것**
- `src/data/` 다섯 파일이 전부 비어 있다. 채우면 바로 돌아간다
- `types.ts` 의 모양이 문항 설계와 안 맞으면 고쳐도 된다.
  코드가 데이터를 따라가는 게 맞다
- 오늘 정해야 할 것 6가지는 `docs/HANDOFF.md` 아래쪽에 정리해뒀다
