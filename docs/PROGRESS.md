# 진행 기록

양쪽에서 각자 작업하고 있어서, **무엇을 했고 무엇을 정했는지** 여기에 남긴다.
서로의 작업이 겹치거나 어긋나는 걸 막는 게 목적이다.

## 쓰는 법

작업을 마치면 맨 위에 항목을 하나 추가한다. 최신이 위로 오게.

```markdown
## YYYY-MM-DD · 누가

**한 것**
- 짧게. 파일 이름을 같이 적으면 좋다

**정한 것**
- 뒤집기 어려운 결정만. 이유를 한 줄 붙인다

**넘기는 것 / 물어볼 것**
- 상대 쪽이 알아야 하거나 결정해줘야 하는 것
```

세 칸 다 채울 필요는 없다. 없으면 지운다.

당장 안 할 거면 타입이나 주석에 "스토리 문항의 traits 는 무시됨" 을 적어두는 것만으로 충분하다.

**(1) 예산을 slots 를 모르는 채로 자른다**

`resolve()` 를 보면 순서가 이렇다.

```
pool = pickForPerson(traits, 100)   // show + aspect 만 본다. slots 는 안 본다
   ↓
장면마다  pool.find(q => fits(q, beat.pick, scene.slot))
   ↓
못 찾으면  return []                // 그 문항 자리가 조용히 사라진다
```

문항이 400개고 장면이 7개면, 뽑힌 100개 안에 특정 장면 slot 문항이 모자라는 일이
실제로 생긴다. 그러면 **그 사람만 문항 수가 줄고** `check:questions` 의
"출제량 편차" 경고로만 뒤늦게 나타난다. 원인이 `show` 조건이 아니라 예산 배분이라
경고 문구("조건이 한쪽으로 쏠렸는지 확인")를 따라가면 엉뚱한 데를 보게 된다.

요청: `pickForPerson` 이 장면들의 slot별 수요를 먼저 계산해서 그만큼 확보하거나,
`resolve` 가 pool 에서 못 찾을 때 전체 `QUESTIONS` 에서 보충하도록 해줄 수 있을까.

**(2) `minPerAspect` 로는 축이 얇아지는 걸 못 막는다**

`aspect` 를 안 적으면 점수 주는 축에서 유추되는데(`aspectsOf`), 한 문항이 축 두 개에
점수를 주면 aspect 도 두 개가 된다. 그래서 **aspect 카운트는 찼는데 특정 축은
여전히 얇은** 상태가 가능하다.

지난 라운드 실측이다. 장소 태그로 필터를 걸었더니 축 하나가 **35문항 중 4문항**까지
떨어졌고, `score.ts` 의 `normalize` 에서 `room <= 0` 이 되어 그 축이 0으로 눌렸다.
결과 코드 한 글자가 사실상 동전 던지기였다.

지금 `check:questions` 의 축별 카운트는 **전체 문항 풀** 기준이다.
문제는 **한 사람에게 실제로 출제된 세트** 에서 생기므로 이 검사로는 안 잡힌다.

요청: 조합별 루프 안에서 "실제 출제된 세트가 축 X를 재는 문항을 몇 개 포함했는가"의
최소값을 같이 봐줄 수 있을까. 판정 기준은 이렇게 썼었다 —
선택지끼리 그 축 점수가 갈리면 "잰다"고 본다 (전부 같은 값이면 뭘 골라도 결과가 같다).

- **장면에 인물 배치** (`cast`) — x/y 비율, 크기, 좌우반전
- **대사 누적 → 질문창** — 터치할 때마다 대사가 쌓이고(앞의 것은 흐려짐),
  다 나온 뒤 질문창이 위로 떠오른다
- **출제 알고리즘** (`engine/select.ts`)
  · 불가능한 상황 차단 (문항 `show`, 장면 `when`, `!` 부정 지원)
  · 역할(`aspect`)별 최소치를 먼저 채우고 나머지 무작위
  · 시간대(`slots` ↔ 장면 `slot`) 매칭
  · 한 장면 연속 문항 상한
- **분량 설정** (`data/survey.ts`) — 전체 120, 스토리 100, 역할당 최소 6
- 채점 결과에 **역할별 문항 수**를 넣었다. 어떤 항목을 2문항만 물었으면
  그 점수는 믿을 게 못 되므로 결과에서 알려줄 수 있다

**확인한 것** (임시 데이터로 돌려봄, 커밋 안 함)
- 아바타 누적 · 직접 수정 · 인물 2명 배치 · 대사 3줄 누적 → 질문창 · 슬라이더 전부 동작
- 남고 조건에서 복도 장면이 통째로 제외되는 것 확인
- 질문창 안 버튼이 밝은 화면용 스타일을 물려받아 흰색으로 튀던 것 수정

**친구 쪽에 요청 / 알림**
- **문항이 300~400개는 필요하다.** 100문항을 매번 다르게, 조건에 맞게 뽑으려면
  조건별·시간대별·역할별로 후보가 충분해야 한다
- 문항마다 `aspect`(무엇을 보는지) · `slots`(어느 시간대) · `show`(누구에게)를
  반드시 붙여야 균등 출제와 필터링이 동작한다
- **불가능한 조합에는 대체 장면·문항이 필요하다.** 남고생만 장면 하나가 빠지면
  그 사람만 문항 수가 적어진다. `check:questions` 가 이걸 잡아준다
- 시작 질문은 **아바타가 눈에 띄게 변하는 순서**로. 첫 질문에 답했는데
  그림이 그대로면 연출이 첫 질문부터 죽는다

**확인한 것**

- `npm run check:questions` 가 축별 문항 부족을 정확히 잡는다.
- 조건부 출제(`show`)도 동작한다.

**문항 설계할 때 참고할 것**
- **시작 질문 순서를 아바타가 눈에 띄게 변하는 순서로 잡는 게 좋다.**
  테스트에서 첫 질문(성별)에 답했는데 그림이 그대로였다. 조각이 없으면
  "답할수록 그려진다"는 느낌이 첫 질문부터 죽는다.
  첫 질문일수록 그림이 확 바뀌는 항목(머리·체형처럼 큰 것)이 낫다.
- 슬라이더는 `steps` 를 홀수로 두면 가운데(중립)가 생긴다.
  가운데를 기본값으로 두므로, 안 움직이고 넘기면 0점 처리된다.
  중립을 허용할지 강제로 고르게 할지는 문항 성격에 따라 정하면 된다.
