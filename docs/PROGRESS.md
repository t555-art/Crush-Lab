# 진행 기록

양쪽에서 각자 작업하고 있어서, **무엇을 했고 무엇을 정했는지** 여기에 남긴다.
서로의 작업이 겹치거나 어긋나는 걸 막는 게 목적이다.

## 쓰는 법

작업을 마치면 맨 위에 항목을 하나 추가한다. 최신이 위로 오게.

```markdown
## YYYY-MM-DD · 누가

**한 것**
- 짧게. 파일 이름을 같이 적으면 좋다

**정한 것**
- 뒤집기 어려운 결정만. 이유를 한 줄 붙인다

**넘기는 것 / 물어볼 것**
- 상대 쪽이 알아야 하거나 결정해줘야 하는 것
```

세 칸 다 채울 필요는 없다. 없으면 지운다.

## 2026-08-14 (3) · 코드 쪽

**정한 것 — 역할 분담**
- 내용(문항·스토리·결과 텍스트)과 미술은 **친구 쪽**
- 기능(엔진·화면·연출·알고리즘·배포)은 **코드 쪽**
- **상대 담당인 일은 직접 하지 않고 요청한다.** 겹치면 나중에 하나를 버려야 한다

**한 것 — 구상을 전부 구현했다**
- **부품 조립 캐릭터** (`engine/character.ts`, `data/parts.ts`)
  완성된 그림 대신 머리·체형·얼굴 부품을 겹친다.
  내 아바타와 스토리 속 상대가 같은 시스템을 쓴다.
  상대의 특성은 `crush.` 를 앞에 붙여 구분한다
- **답할수록 아바타 구체화** — 시작 질문에 답하면 부품이 하나씩 붙는다
- **아바타 직접 다듬기** — 자동 선택 위에 사용자가 덮어쓴다 (`self.<슬롯>`)
- **장면에 인물 배치** (`cast`) — x/y 비율, 크기, 좌우반전
- **대사 누적 → 질문창** — 터치할 때마다 대사가 쌓이고(앞의 것은 흐려짐),
  다 나온 뒤 질문창이 위로 떠오른다
- **출제 알고리즘** (`engine/select.ts`)
  · 불가능한 상황 차단 (문항 `show`, 장면 `when`, `!` 부정 지원)
  · 역할(`aspect`)별 최소치를 먼저 채우고 나머지 무작위
  · 시간대(`slots` ↔ 장면 `slot`) 매칭
  · 한 장면 연속 문항 상한
- **분량 설정** (`data/survey.ts`) — 전체 120, 스토리 100, 역할당 최소 6
- 채점 결과에 **역할별 문항 수**를 넣었다. 어떤 항목을 2문항만 물었으면
  그 점수는 믿을 게 못 되므로 결과에서 알려줄 수 있다

**확인한 것** (임시 데이터로 돌려봄, 커밋 안 함)
- 아바타 누적 · 직접 수정 · 인물 2명 배치 · 대사 3줄 누적 → 질문창 · 슬라이더 전부 동작
- 남고 조건에서 복도 장면이 통째로 제외되는 것 확인
- 질문창 안 버튼이 밝은 화면용 스타일을 물려받아 흰색으로 튀던 것 수정

**친구 쪽에 요청 / 알림**
- **문항이 300~400개는 필요하다.** 100문항을 매번 다르게, 조건에 맞게 뽑으려면
  조건별·시간대별·역할별로 후보가 충분해야 한다
- 문항마다 `aspect`(무엇을 보는지) · `slots`(어느 시간대) · `show`(누구에게)를
  반드시 붙여야 균등 출제와 필터링이 동작한다
- **불가능한 조합에는 대체 장면·문항이 필요하다.** 남고생만 장면 하나가 빠지면
  그 사람만 문항 수가 적어진다. `check:questions` 가 이걸 잡아준다
- 시작 질문은 **아바타가 눈에 띄게 변하는 순서**로. 첫 질문에 답했는데
  그림이 그대로면 연출이 첫 질문부터 죽는다

## 2026-08-14 (2) · 코드 쪽

**한 것**
- 슬라이더와 아바타를 임시 데이터로 실제로 돌려봤다. (임시 데이터는 커밋 안 함)
- **슬라이더를 다시 만들었다.** 터치 높이가 16px밖에 안 돼서 손가락으로 쓰기 나빴다.
  48px로 키우고 손잡이를 26px로 만들었다. 눈금이 트랙과 따로 놀던 것도 겹쳐서 정리했다.
  이제 끌어도 되고 트랙 아무 데나 탭해도 그 자리로 간다.

**확인한 것**
- 아바타 누적은 잘 된다. 답할 때마다 조각이 하나씩 켜진다.
- `npm run check:questions` 가 축별 문항 부족을 정확히 잡는다.
- 조건부 출제(`show`)도 동작한다.

**문항 설계할 때 참고할 것**
- **시작 질문 순서를 아바타가 눈에 띄게 변하는 순서로 잡는 게 좋다.**
  테스트에서 첫 질문(성별)에 답했는데 그림이 그대로였다. 조각이 없으면
  "답할수록 그려진다"는 느낌이 첫 질문부터 죽는다.
  첫 질문일수록 그림이 확 바뀌는 항목(머리·체형처럼 큰 것)이 낫다.
- 슬라이더는 `steps` 를 홀수로 두면 가운데(중립)가 생긴다.
  가운데를 기본값으로 두므로, 안 움직이고 넘기면 0점 처리된다.
  중립을 허용할지 강제로 고르게 할지는 문항 성격에 따라 정하면 된다.

## 2026-08-14 · 코드 쪽

**한 것**
- 검사 내용을 전부 삭제하고 빈 상태로 되돌렸다.
  지운 것: 옛 문항 364개, 크리스탈 16유형, 축 4개, 하루 서사 7장면,
  요정 캐릭터, 관련 자리표시자 이미지, 옛 `index.html` 추출 도구
- 데이터 계약을 새로 짰다 (`src/engine/types.ts`)
  - 선택지형 + 슬라이더형 문항
  - 특성(traits) — 아바타·상대 묘사·출제 조건에 함께 쓰임
  - 아바타 레이어 (`src/data/avatar.ts`)
  - 그림 조건부 교체 (`ArtSlot.variants`)
- 채점을 축 개수와 무관하게 돌도록 고쳤다. 축은 `src/data/axes.ts` 에서 읽는다
- 슬라이더 UI와 아바타 누적 렌더링을 붙였다 (`src/scripts/player.ts`)
- `npm run check:questions` 를 새 스키마에 맞게 다시 만들었다.
  아무에게도 안 나가는 문항, 사람마다 출제량 차이까지 잡는다
- 인수인계 문서를 썼다 (`docs/HANDOFF.md`)

**정한 것**
- 데이터 파일을 JSON 대신 TS로 뒀다. 타입이 걸려서 오타·형식 오류가
  빌드에서 잡히고, 파일 안에 설명을 주석으로 남길 수 있다
- 채점 정규화(무작위 기댓값 대비)는 유지했다. 조건부 출제 구조에서는
  이게 없으면 "어떤 문항이 뽑혔는지"가 결과에 섞인다

**넘기는 것**
- `src/data/` 다섯 파일이 전부 비어 있다. 채우면 바로 돌아간다
- `types.ts` 의 모양이 문항 설계와 안 맞으면 고쳐도 된다.
  코드가 데이터를 따라가는 게 맞다
- 오늘 정해야 할 것 6가지는 `docs/HANDOFF.md` 아래쪽에 정리해뒀다
